# Internationalisation (i18n) - Documentation

## Vue d'ensemble

Le client web AREA supporte l'anglais et le français. La langue est détectée automatiquement depuis le navigateur et peut être changée via le sélecteur de langue.

## Utilisation de base

### Dans un composant

```typescript
import { useTranslation } from '@/contexts/I18nContext';

function MyComponent() {
  const t = useTranslation();

  return (
    <div>
      <h1>{t('navigation.home')}</h1>
      <p>{t('common.loading')}</p>
    </div>
  );
}
```

### Avec des paramètres dynamiques

```typescript
const t = useTranslation();

// Dans le fichier de traduction: "welcome": "Welcome back, {{name}}!"
return <h1>{t('dashboard.welcome', { name: user.name })}</h1>;
```

### Changer la langue manuellement

```typescript
import { useI18n } from '@/contexts/I18nContext';

function LanguageSettings() {
  const { locale, setLocale } = useI18n();

  return (
    <div>
      <button onClick={() => setLocale('en')}>English</button>
      <button onClick={() => setLocale('fr')}>Français</button>
      <p>Current: {locale}</p>
    </div>
  );
}
```

## Structure des fichiers

### Emplacement

- `packages/web/src/locales/en.json` - Traductions anglaises
- `packages/web/src/locales/fr.json` - Traductions françaises
- `packages/web/src/contexts/I18nContext.tsx` - Contexte de traduction

### Organisation des clés

Les clés sont organisées par domaine fonctionnel :

```json
{
  "common": {
    "save": "Save",
    "cancel": "Cancel"
  },
  "navigation": {
    "home": "Home",
    "dashboard": "Dashboard"
  },
  "auth": {
    "login": {
      "title": "Sign in",
      "email": "Email"
    }
  }
}
```

## Ajouter une nouvelle traduction

### 1. Ajouter la clé dans les deux fichiers

**en.json**
```json
{
  "myFeature": {
    "title": "My Feature",
    "description": "This is a description"
  }
}
```

**fr.json**
```json
{
  "myFeature": {
    "title": "Ma fonctionnalité",
    "description": "Ceci est une description"
  }
}
```

### 2. Utiliser la traduction

```typescript
const t = useTranslation();

return (
  <div>
    <h1>{t('myFeature.title')}</h1>
    <p>{t('myFeature.description')}</p>
  </div>
);
```

## Clés disponibles

### common
Termes génériques réutilisables (save, cancel, delete, loading, etc.)

### navigation
Labels de navigation (home, dashboard, profile, admin, etc.)

### auth.login / auth.register
Textes des pages d'authentification

### dashboard
Contenu du tableau de bord

### area
Gestion des automatisations

### createArea
Création d'automatisations

### services
Gestion des services connectés

### profile
Page de profil utilisateur

### admin
Panel d'administration

### about
Page à propos

### errors
Messages d'erreur

### validation
Messages de validation de formulaires

## Détection de la langue

La langue est déterminée dans cet ordre :

1. Langue sauvegardée dans `localStorage` (clé: `area:locale`)
2. Langue du navigateur via `navigator.language`
3. Anglais par défaut

## Bonnes pratiques

### Utiliser des clés descriptives

```typescript
// Bon
{t('auth.login.invalidCredentials')}

// Éviter
{t('error1')}
```

### Utiliser des paramètres pour les valeurs dynamiques

```typescript
// Bon
{t('welcome', { name: user.name })}

// Éviter
{`Welcome ${user.name}`}
```

### Ne pas concaténer de traductions

```typescript
// Bon
{t('area.confirmations.delete', { name: area.name })}

// Éviter
{t('confirm')} {area.name} {t('delete')}
```

### Regrouper par domaine fonctionnel

Organisez les clés par page ou fonctionnalité pour faciliter la maintenance.

## Gestion des erreurs

Si une clé de traduction n'existe pas :
- La clé elle-même est retournée
- Un warning est affiché dans la console

```typescript
t('missing.key') // Retourne "missing.key" et affiche un warning
```
